# Verifying without a headset

## Layers
1. **Pure logic:** `node file.ts` (Node ≥ 22 strips types) or esbuild: `esbuild x.ts --bundle --platform=node --format=esm --alias:@app=./src --outfile=.tmp/x.mjs && node .tmp/x.mjs`. Simulations, parsers, scoring, regression asserts. Fixtures can be generated by a small Python script.
2. **Three.js-dependent maths headless:** bundle with `--alias:@iwsdk/core=three` and stub `document.createElement` for canvas textures.
3. **XR with emulated hands:** the dev server (`npx @iwsdk/cli dev up --ai-mode agent`, headless; `collaborate` when the user watches) driven from Python with `scripts/xr_e2e_lib.py`.
4. **Visual review:** runtime screenshots (`browser screenshot`, not the editor's `scene screenshot`) after every visual change, dev review cameras, state presets, Blender renders for A/B. Crop or thumbnail big screenshots (≤ ~900 px) before reading.

## Harness contract (what the app logs, dev only)
`console.info(\`[${TAG}] #${pageId}.${seq} ${event} key=value … layout=${json}\`)`
- `pageId` random per page load; `seq` increments on every line.
- Log every state transition, score and result, and the **world positions** of everything the test must touch.
- The log buffer survives reloads and CLI calls take ~1–2 s each, so naive matching gives false PASSes and timeouts. The library therefore: asks for `browser logs {"since": <ms>, "pattern": "\\[TAG\\]", "count": 200}`; pins the newest `pageId` after a reload; accepts only lines whose `seq` is above the last one consumed.

## CLI cheat sheet (`npx @iwsdk/cli …`, or `node_modules/.bin/iwsdk`)
| Need | Command | Gotcha |
|---|---|---|
| Hands only | `xr set-input-mode {"mode":"hand"}`, `xr set-hand-pose {"device":"hand-right","poseId":"point"}` | re-apply after `set-device-state`; entering XR resets device poses |
| Seat the user | `xr set-transform {"device":"headset","position":…,"orientation":…}` | do it after `xr enter` |
| Pinch tap | `xr select {"device":"hand-right"}` | |
| Move a fingertip exactly | `xr animate-to {"device":"hand-right","anchor":"index-tip","position":{…},"duration":0.3}` | XR-origin metres, −Z forward |
| Paths, grabs, presses | `xr run-sequence {"device":…,"steps":[…]}` | name an `anchor` (`index-tip`, `grasp`) in the first positioned step of every call (it carries over within a call); IWER gives up **28 s** after dispatch, so chunk at about 18 s; the idle hand drops to the hip; `dryRun:true` checks a plan |
| Press a UI element | step `{"target":"<id>","press":{}}` | ids from `xr list-targets` (ECS entities and UIKit ids only); press with the off hand |
| Grab | step `{"target":"piece","pinch":{"value":1,"at":"arrival"}}`, then `pinch 0` | |
| Microgesture | `xr microgesture {"device":"hand-right","gesture":"tap"}` | `swipe-left/right/forward/backward`, `tap`; hand raised side-on in view |
| Hand state | `xr get-hand-state {"device":"hand-right"}` | pinch value, select, tip positions |
| Keys | `browser interact {"steps":[{"action":"press","key":"1"}]}` | dev keys for rare states |
| Logs | `browser logs {"since":<ms>,"pattern":"…","count":200}` | count ≤ 200; `since` is ms since epoch |
| Enter / exit | `xr enter`, `xr exit`, `xr status` | with `offer:"always"` the session is re-offered after exit |
| Screenshot | `browser screenshot --output-file artifacts/x.png` | look at every one after a visual change |
| Reload | `browser reload` | then re-pin the page id |
| Preset | `browser run tools/goto.mjs` | needs `dev restart --allow-browser-automation` (architecture.md) |

## Rules that saved hours
- **Never edit `src/` while a run is going** (comments included). Docs, skills and `public/` assets outside the import graph are safe. If you slipped, restart the run.
- Run long suites in the background (`npm run test:xr`) and write docs meanwhile; wait for the completion notice.
- Quick run (one item + the changed feature) after each change; the full suite before each commit.
- Each feature gets a flag (`--negative`, `--hand left`, `--jitter 5`) so one command runs everything.

## Minimum matrix before calling it done
1. The full journey, right hand, with 3–6 mm random fingertip error.
2. Negative cases (wrong target, too fast, wrong order), each giving its specific hint.
3. Left hand.
4. Placement three ways: no table, seated at a table, a round table.
5. Menus by poke and by pinch-ray, including switching modes.
6. Every secret or advanced mechanic, seen and unseen; win, lose and restart.
7. User-content paths if any.
8. Production build: `npm run build`, `vite preview` serves everything, dev logs absent from the bundle.

## What only a headset can prove (keep this list in `docs/TESTING.md`, tick it on the device)
72 fps (60 floor) during the heaviest effect; text and models render under multiview; contact and pinch thresholds with real hands; tracking at gesture extremes (under the table, edge of view); two different rooms; depth occlusion; text legibility at distance; hand-tracking permission prompt; system-menu pause; TTS voices; the file picker in Quest Browser; microgestures; the production URL logged out.
