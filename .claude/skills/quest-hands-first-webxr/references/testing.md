# Verifying without a headset

## Layers
1. **Pure logic:** `node file.ts` (Node ≥ 22 strips types) or esbuild: `esbuild x.ts --bundle --platform=node --format=esm --alias:@app=./src --outfile=.tmp/x.mjs && node .tmp/x.mjs`. Simulations, parsers, scoring, regression asserts. Fixtures can be generated by a small Python script.
2. **Three.js-dependent maths headless:** bundle with `--alias:@iwsdk/core=three` and stub `document.createElement` for canvas textures.
3. **XR with emulated hands:** the dev server (`npx @iwsdk/cli dev up --ai-mode agent`, headless; `collaborate` when the user watches) driven from Python with `scripts/xr_e2e_lib.py`.
4. **Visual review:** runtime screenshots (`browser screenshot`, not the editor's `scene screenshot`) after every visual change, dev review cameras, state presets, Blender renders for A/B. Crop or thumbnail big screenshots (≤ ~900 px) before reading.

## Harness contract (what the app logs, dev only)
`console.info(\`[${TAG}] #${pageId}.${seq} ${event} key=value … layout=${json}\`)`
- `pageId` random per page load; `seq` increments on every line.
- Log every state transition, score and result, and the **world positions** of everything the test must touch.
- The log buffer survives reloads and CLI calls take ~1–2 s each, so naive matching gives false PASSes and timeouts. The library therefore: asks for `browser logs {"since": <ms>, "pattern": "\\[TAG\\]", "count": 200}`; pins the newest `pageId` after a reload; accepts only lines whose `seq` is above the last one consumed.

## CLI cheat sheet (`npx @iwsdk/cli …`, or `node_modules/.bin/iwsdk`)
| Need | Command | Gotcha |
|---|---|---|
| Hands only | `xr set-input-mode {"mode":"hand"}`, `xr set-hand-pose {"device":"hand-right","poseId":"point"}` | re-apply after `set-device-state`; entering XR resets device poses |
| Seat the user | `xr set-transform {"device":"headset","position":…,"orientation":…}` | do it after `xr enter` |
| Pinch tap | `xr select {"device":"hand-right"}` | |
| Move a fingertip exactly | `xr animate-to {"device":"hand-right","anchor":"index-tip","position":{…},"duration":0.3}` | XR-origin metres, −Z forward |
| Paths, grabs, presses | `xr run-sequence {"device":…,"steps":[…]}` | name an `anchor` (`index-tip`, `grasp`) in the first positioned step of every call (it carries over within a call); IWER gives up **28 s** after dispatch, so chunk at about 18 s; the idle hand drops to the hip; `dryRun:true` checks a plan |
| Press a UI element | step `{"target":"<id>","press":{}}` | ids from `xr list-targets` (ECS entities and UIKit ids only); press with the off hand |
| Grab | step `{"target":"piece","pinch":{"value":1,"at":"arrival"}}`, then `pinch 0` | |
| Microgesture | `xr microgesture {"device":"hand-right","gesture":"tap"}` | `swipe-left/right/forward/backward`, `tap`; hand raised side-on in view |
| Hand state | `xr get-hand-state {"device":"hand-right"}` | pinch value, select, tip positions |
| Keys | `browser interact {"steps":[{"action":"press","key":"1"}]}` | dev keys for rare states |
| Logs | `browser logs {"since":<ms>,"pattern":"…","count":200}` | count ≤ 200; `since` is ms since epoch |
| Enter / exit | `xr enter`, `xr exit`, `xr status` | with `offer:"always"` the session is re-offered after exit |
| Screenshot | `browser screenshot --output-file artifacts/x.png` | look at every one after a visual change |
| Reload | `browser reload` | then re-pin the page id |
| Preset | `browser run tools/goto.mjs` | needs `dev restart --allow-browser-automation` (architecture.md) |

## Rules that saved hours
- **Unattended runs: headless.** A headed managed browser stops drawing when the screen locks or the window is hidden. The app logs one frame and freezes (e.g. stuck at "finding your desk") with **no errors**. Use `npx iwsdk dev restart --headless --open --allow-browser-automation` for long or overnight test runs; switch back to headed (and say so) when the user wants to watch.
- **Never edit `src/` while a run is going** (comments included). Docs, skills and `public/` assets outside the import graph are safe. If you slipped, restart the run.
- Run long suites in the background (`npm run test:xr`) and write docs meanwhile; wait for the completion notice.
- Quick run (one item + the changed feature) after each change; the full suite before each commit.
- Each feature gets a flag (`--negative`, `--hand left`, `--jitter 5`) so one command runs everything.

## Minimum matrix before calling it done
1. The full journey, right hand, with 3–6 mm random fingertip error.
2. Negative cases (wrong target, too fast, wrong order), each giving its specific hint.
3. Left hand.
4. Placement three ways: no table, seated at a table, a round table.
5. Menus by poke and by pinch-ray, including switching modes.
6. Every secret or advanced mechanic, seen and unseen; win, lose and restart.
7. User-content paths if any.
8. Production build: `npm run build`, `vite preview` serves everything, dev logs absent from the bundle.

## Meta VR CLI on the device (works on Linux)
The `metavr` binary installs to `~/.metavr/npm/binaries/@meta-quest__metavr-linux-x64/<version>/metavr` and is not on PATH.
```
metavr device list ; metavr device configure-testing setup        # stay awake; "restore" afterwards
metavr adb reverse tcp:8081 tcp:8081 ; metavr device browser http://localhost:8081
metavr perf capture --app com.oculus.browser --mode vr --duration 10000 -o run1
metavr perf analyze-trace --focus frames ; metavr perf open <id>
metavr shell ovrgpuprofiler --realtime="29,30"                   # vertex vs fragment load
metavr capture video start --width 1920 --height 1080 ; metavr capture video stop
metavr capture screenshot -o shot.png --width 1920 --height 1080
metavr casting start | status | stop
```
For CPU frame time in the browser: `chrome://inspect#devices`, then "trace" on com.oculus.browser with the `xr.debug` category.
- `metavr asset search` (Meta's 3D Asset Library) failed server-side for us in Nov 2026, even when logged in. Retry occasionally; don't depend on it.
- Meta Spatial Simulator runs 2D Android apps only (macOS/Windows); it can't test WebXR. Use IWER.

## More harness lessons (Sadak VR, Nov 2026)
- **`browser run` scripts see the editor shell first:** the app runs in an iframe (`…?__iwsdk_preview_reload=…`). Evaluate in every `page.frames()` and keep the one where your debug handle (`window.<app>`) exists. Reference: `sadak-vr/tools/probe.mjs`.
- **`browser logs` `pattern` is not reliable for every line**: when a one-off line seems missing, fetch without a pattern or probe state via the debug handle before concluding the code didn't run.
- **Review shots need a realistic pose.** The test seat (head 1.0 m, pitched about 45° down) hides faces and makes UI look as if it overlaps. For composition review, put the eyes 1.2 m above the floor, about 0.45 m behind the table edge, pitched −5° to −10° (`sadak-vr/scripts/e2e/review.py`). The emulator room's table is a 0.42 m coffee table: standing characters will loom over it.
- **Dev shortcuts must respect state** (e.g. "put exact change on the plate" pays only what is missing); a naive shortcut produced a false failure that looked like a game bug.

- **Tests must reset world state the desktop preview changed.** The 2D page runs the same journey (e.g. auto-hails after 3 s), so entering XR found the vehicle already parked. Reset vehicles and one-shot state on every new journey and on "play again".
- Drive a generic loop from the app's own logs (`phase X errand=Y step=N`, `result points=`, `targets … layout={buttons:{…}}`) so one driver plays any level. Press UIKit buttons by poking their logged positions, and fall back to `xr run-sequence {target, press}`; count both paths.
- Physical-randomness checks (which coin the grab takes) can't be forced: verify the rule whenever it occurs (every overpayment got change back) rather than failing when it doesn't happen.

## Recording a trailer from the emulator (Linux, no headset)
The rules accept emulator footage ("as viewed on a Meta Quest device or via XR Simulator or another equivalent emulator"). The reference implementation is in Hands of a Master: `tools/trailer/recorder.mjs`, `shoot.py` and `assemble.py`.
- **One shot per `browser run`:** scripts are capped at 110 s per lease.
  - Set the viewport to 1920×1080 *before* the session starts; a running session keeps its canvas size.
  - Reload with a preset, then make one trusted `page.mouse.click`, or Chrome keeps the app's audio locked.
  - Grant the offered session (`IWER_DEVICE.grantOfferedSession()`).
  - Hide `IWER_DEVICE.devui` (canvas and container) and the workspace chrome around the runtime iframe.
- **Frames:** use the CDP `Page.startScreencast` (JPEG plus timestamps, 25–50 fps on a GPU). Encode them with an ffconcat file with per-frame durations, then `fps=30`.
- **App log during a shot:** the CLI's log reader waits while the script holds the lease, so capture `page.on('console')` to a file and drive the shot from that. Use the *latest* layout line: a preset can switch songs or lessons after the first one is logged.
- **Camera:** set the head with `xr set-transform` before the reload (the emulator restores it, so the desk is placed in front of a seated viewer). Aim it after the session starts. Use `xr animate-to {device: "headset", orientation: {pitch, yaw, roll}, easing: "minimum-jerk"}` for push-ins.
- **Audio:**
  - The headless managed browser runs with `--mute-audio`, so record **headed** with the screen awake.
  - Route Chromium to a null sink: `pactl load-module module-null-sink sink_name=rec`, then `pactl move-sink-input <id> rec`. New Chromium streams follow (stream-restore).
  - Record with `ffmpeg -f pulse -i rec.monitor`.
  - **Move the streams back and unload the sink afterwards,** or Chromium stays silent for the user.
